Architecture & Approach · V2 · Claude Agent SDK

Prospect Engine

A Claude-powered sales intelligence system for CGVAK: it turns account research into evidence-backed signals, assembles a versioned Account Context, qualifies across six dimensions, and produces an approved Strategy that Outreach and Sales Prep execute — not invent. A human approves every message; La Growth Machine sends it.

For: CGVAK outbound sales Prepared for: Bertie Status: Draft approach — v2 Model: Claude, via Agent SDK
What changed in V2: this revision folds in CGVAK's internal V2 strategy review. Three structural shifts worth knowing before you read on — qualification is no longer a single MAN score, it's six dimensions that combine into an Opportunity Priority, with MAN kept as an optional legacy view; a new Strategy Agent now sits between qualification and action, so Outreach and Sales Prep stop improvising the play; and every signal that drives a decision is now traceable to dated, sourced evidence instead of being asserted outright.
01 — The mechanism

Fourteen steps, one governed loop

Research still fans out in parallel, but nothing reaches a rep's inbox on inference alone. Findings become evidence-linked signals, signals assemble into one versioned Account Context, qualification and strategy are kept as separate decisions, and an automated evaluation pass checks the draft before a human ever sees it. Outcomes flow back into memory, so the next account benefits from this one.

02 — Inputs

What the agent needs before it starts

Five assets. The first is per-target; the rest are configuration — set up once, reused on every run.

Target

Company list or single account — a name, domain, or a CSV, resolved against existing CRM records to skip duplicates.

Context

CGVAK business profile & ICP — proof points and who counts as a good-fit buyer.

Services

Service catalog — the offerings the pitch layer chooses from, e.g. EIA, each with the proof points it's sold on.

Writing

Writing samples — real emails or LinkedIn messages you've sent, used as a reference so drafts read like something you'd actually send.

Rules

Sales rules — qualification thresholds, no-go lists, cadence limits, compliance constraints. Qualification, Strategy, and Outreach all read from this.

06 — Strategy layer

A separate decision: how do we pursue it

Qualification answers "is this worth pursuing?" Strategy answers "how should we pursue it?" — a different question, with its own agent and its own object. Outreach and Sales Prep read this object; they don't get to invent one. An account rarely has one buyer, so Strategy doesn't produce one play: it weighs every mapped persona against the service catalog and decides how many threads are worth running at once.

07 — Outreach & Sales Prep

Execution of the strategy, not invention of one

Both agents consume the same approved Strategy object — one instance per active thread. A default six-touch, fifteen-day cadence mixes LinkedIn and email; the rules asset controls timing and touch count. Once approved at the human gate, each thread's sequence is pushed to La Growth Machine, which runs the LinkedIn steps and email sends and reports back opens, replies, and connection status.

11 — Memory architecture

Three stores, kept separate on purpose

Mixing these makes the system unable to tell "true for CGVAK" from "true for this one account" from "true across many deals" — which is exactly the distinction Strategy and Qualification depend on.

Enterprise Memory

CGVAK's own facts — services, capabilities, ICP, industries, case studies, proof points, sales methodology, approved messaging.

Account Memory

Per-account history — company facts, people, conversations, previous outreach, objections, responses, opportunities, historical signals.

Sales Learning

Cross-account patterns — which signals predict meetings, personas that respond, angles that convert, false-positive signals, service-line performance.

12 — Build sequence

Five gates, not one big build

Each gate is a question a senior BDE could answer honestly about the system — not a ship date.

Intelligence

Account resolution, parallel research, signal extraction, and the evidence model.

gate: can the system reliably understand an account?

Qualification

Context builder plus Fit, Intent, Timing, Buyer, Commercial, and Engagement scoring.

gate: does it identify worthwhile prospects against a human baseline?

Strategy

Persona, problem hypothesis, trigger, CGVAK capability, positioning, and CTA.

gate: would a senior BDE agree with the recommended play?

Content

LinkedIn, email, call prep, and pitch generation, all from the strategy object.

gate: would the BDE actually use the output?

Closed loop

Execution events, replies, meetings, opportunities, wins/losses, and learning.

gate: does the system improve targeting and strategy over time?

13 — Technical pattern

Claude reasons; the application governs

Agent SDK for orchestration and reasoning — but business-critical state and rules live outside the model. Agent outputs are schema-constrained; the application owns workflow state, permissions, approval state, scoring config, evidence records, audit logs, and execution authorization.

Research fan-out Parallel Agent SDK sub-agents, one per research domain, each scoped to its own tool set (web_search, fetch); an orchestrator merges and dedupes.
Decision-maker enrichment Sub-agent calls a contact-data provider as a tool — Apollo.io or ContactOut — resolving each contact to verified email, phone, and LinkedIn profile.
Evidence store Source-backed facts and signal provenance, persisted outside the model — separate from any generated interpretation.
Context builder Retrieval + compression service that assembles the versioned Account Context per run, rather than handing every agent the full research corpus.
Rules / scoring service Deterministic qualification math and policy enforcement, outside the model — a config file, not a prompt, so it's auditable and swappable.
Service / proof repository The Services input as a real repository — CGVAK capabilities, case studies, and approved claims the Strategy and Pitch layers select from.
Evaluation store Agent scores, failures, human edits, and rejection reasons — the record the Evaluation Agent and Learning Layer both draw on.
Human gate Application-level approval, not a prompt instruction — the La Growth Machine send tool is unreachable until a rep confirms.
Execution adapter Approved cadence pushed to La Growth Machine via its API; isolated send capability, available only post-approval, with its own rate limits and reply tracking.
CRM integration MCP connector (HubSpot / Salesforce) as a tool call, writing structured records — additive and versioned, never overwriting rep notes.
Learning store Validated cross-account patterns only — nothing here changes production scoring or strategy without a review pass.
